Claude Code 的工作空间信任与运行模式

在终端使用 Claude Code 前要确认工作空间信任，并按风险选择审批强度。

01

理解概念

回到当时的问题

第一次在机房终端启动 Claude Code，担心它未经允许改文件，应该选哪种运行模式？

启动前：信任工作空间

在终端首次进入某个目录使用 Claude Code 时，会要求确认是否信任该工作空间；确认后它才能读取文件、执行命令。

不确定目录内容或来源时，先只让它做只读查看，确认行为符合预期后再授权修改。

运行模式：审批与自动化的取舍

需要逐步审批的模式会在每次工具调用前询问，安全性高，适合不熟悉的目录或敏感操作。

自动接受编辑、跳过权限校验的模式减少甚至取消确认，自动化程度高，但误改、误删和越权操作的风险也更高。

选择建议

日常小改动先用逐步审批；只有任务范围明确、目录可回滚时，才考虑更高自动化。

02

把概念放进示例

01在陌生目录里先只读确认

在机房第一次使用终端 AI 工具，先确保它不会误改文件。

  1. 启动 Claude Code，确认工作空间信任。
  2. 选择需要逐步审批的模式。
  3. 让它只读地查看目录，确认行为符合预期后再授权修改。

得到什么
工具在授权范围内工作，每次改动前都有确认。

A MOMENT TO RECALL

运行模式主要在哪些目标之间取舍？

想一想，再展开答案

在审批强度和自动化程度之间取舍；自动化越高，确认越少，风险越大。
